# Frozen acceptance publication checks, 2026-10-20

The [initial-point acceptance tools](../../tests/crpropa/ACCEPTANCE.md) are
prepared for external multicore Linux execution. This is verification of the
launcher, statistics and frozen inputs, not a completed physical acceptance
campaign. No new primary histories were generated by these checks.

The canonical protocol SHA-256 remains
`e5f345a2773745790f7c59e6941b143cb70450e80a42af38a28aac11deef76a9`.
Regenerating it from the audited native matrix produced an identical file.
Bins, means, normalizations, seeds, tolerances, confidence family and the
200000-history cap were not changed for publication.

Confirmed short checks:

- All seven acceptance bookkeeping/statistics tests pass, including cap and
  seed accounting, complete-history aggregation, equivalence boundaries,
  duplicate-campaign rejection, raw-output report reconstruction and
  incomplete-result handling and retained-library search paths.
- All six pilot bookkeeping tests and the shared photon-table control pass.
- The external shell wrapper passes `bash -n`.
- Plan-only validation verifies the original input bundle, retained pinned
  CRPropa reference binary/data and deterministic output hashes. It produces
  272 jobs: 136000 new primary histories per background/program, with no
  execution and no campaign-ledger reservation.
- All ten current native coefficient exports match the frozen Linux exports
  under the unchanged 5e-12 relative identity guard. These cover five energy
  grid nodes for each of CMB and CMB+Inoue12 and take 42.52 s with two local
  workers. They are deterministic exports, not transport histories.

The local publication checks use macOS arm64, Python 3.12.14, NumPy 2.5.4,
SciPy 1.18.1 and GitPython 3.2.1. The coefficient producer is the dedicated
Release build of the production code published at `6cce391`; input and
reference provenance is frozen by the protocol. The server instructions
retain the prior reference environment's NumPy 2.2.6, SciPy 1.15.3 and
GitPython 3.2.0. Actual dependency versions are recorded in each run.

The Linux launcher fetches the requested public commit into a clean checkout,
builds it, runs CTest and Python controls, and repeats coefficient verification
before reserving the fixed MC campaign. Ubuntu 22.04 stock Boost 1.74,
OpenSSL 3 and CMake 3.22 are supported by the current build helper. The prior
[YAML/OpenSSL regression checks](yaml_configuration.md) passed 144/144 on
macOS and Ubuntu 22.04; publishing these Python tools does not change the
production transport kernels.

The retained CRPropa probe has an absolute RUNPATH pointing to its original
server build. Reference jobs now explicitly load `libcrpropa.so` from the
supplied retained reference directory. The original pilot archive manifest's
library fingerprint is checked before histories and included in resume
identity. This prevents a relocated archive from using an unrelated library.
The Ubuntu runtime prerequisites include single-precision FFTW. Statistical
protocol bytes, table payloads and numerical targets remain unchanged.

This campaign isolates Fe56 PD+decays and both photon sources at one energy
and distance on two backgrounds. It excludes GZK, PPP and EM propagation.
Read the resulting `acceptance-report.json` for agreement, disagreement or
inconclusive. Successful execution, deterministic coefficient identity and
the fixed-job plan alone do not establish physical acceptance or a Release
verdict. Do not restart a campaign to obtain a pass or delete its ledger.
